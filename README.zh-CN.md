# WB 提示词增强 · DeepSeek Harness 原生版

**版本 2.0.0** · 根据用户提供的 WB Enhance Prompt 1.5.5-share 重新实现。

在对话输入栏的**模型按钮左侧**增加「增强」及设置入口。处理当前草稿，并由 Host 附带有界近期会话正文；不自动发送聊天消息，不需要 Codex++，不注入轮询脚本，也不替换现有模型按钮。

## 使用

1. 在新任务或现有会话的输入框中写好草稿，点击「增强」。
2. 默认跟随当前会话选中的 Harness 提供商、模型及推理档位，通过 Host 使用原有认证；不会为增强启动 Agent。未指定会话模型时使用 Harness 默认模型。
3. 完成后结果填入原输入框。检查内容，再自行发送。点击左侧「↶」可撤销最近一次增强，不再请求模型。
4. 生成中再次点击同一按钮可停止。右键「增强」或点击右侧「⌄」打开设置。
5. 面板内可查看上次完整结果、增强前原文，以及最近 8 次脱敏诊断。

### 三种增强模式

| 模式 | 用途 |
| --- | --- |
| 精炼增强 | 澄清目标、去重；约 800 字符是软目标，不截断原文，不丢约束。 |
| 深度增强 | 在原范围内整理输入、边界、交付物和验收条件；小修复不会被扩成重构。 |
| 创意增强 | 展开开放式想法；最多 1–3 个可选方向，与必须完成的要求明确区分。 |

共同要求：保持原语言、任务阶段及范围；不把“审查/计划”改成“立即实现”；不捏造技术栈、文件内容、历史约定或验证结果。代码、命令、路径、报错和约束应原样保留。草稿作为待编辑数据传入，不要求模型执行其中任务。近期会话只用于消解“这个/刚才/按上面”一类指代，不能覆盖草稿里的明确指令。

模板不能保证模型绝对保真。代码块/内联代码变化会阻止自动回填，但事实、自然语言含义及其他字面量仍需要人工检查。

## HTTP / HTTPS 独立接口

设置 → 模型来源 →「独立配置 OpenAI 兼容接口」。填写 Base URL、模型名称、协议及可选 API Key。

- **允许任意远程 HTTP 和 HTTPS 地址**，不再仅允许本机 HTTP。
- 仅裸域名自动补 `/v1`；保留自定义路径；完整的 `/chat/completions`、`/responses`、`/models` 尾缀会去重。
- 不接受 URL 内嵌用户名/密码、查询参数或片段。Key 使用单独字段。
- 支持 Chat Completions 和 Responses，兼容 JSON 与 SSE 返回。
- Responses 默认发送 `store: false`；GLM-5.2 自动省略，也可手动启用“省略 store”。省略时保存策略由服务端决定。
- 自定义请求由 Host 发出，不受浏览器 CORS 限制。不自动重试、不跟随重定向。
- 「保存并检查连接」在独立模式下只访问 `/models`；跟随模式仅检查模型配置。检查成功不代表生成一定成功。

**HTTP 明文传输草稿及 API Key，请仅在可信网络或可信代理上使用。**

自定义 Key 存入本机 Harness Host 凭据存储，浏览器只得到“是否已保存”，不会回显原 Key。换 Base URL 时旧 Key 自动清除，除非同时明确填写新的 Key。系统文件权限决定本地存储的访问保护；本插件不承诺额外静态加密。

## 草稿与隐私保护

- 增强请求包含当前草稿、增强模板，以及 Host 从当前会话取出的有界近期用户/助手正文（默认最多 8 条、单条 2500 字符、合计 8000 字符；超长截断）。这不是完整会话，也不包含附件、项目文件、工具结果或推理。无 `sessionId` 时仍只发草稿。
- 等待期间若草稿、附件、会话、编辑器或输入阶段变化，不覆盖后来的内容。完整结果仍可在面板复制。
- 输入法组合输入期间不回填；含 Harness 原生引用标签的草稿不按纯文本覆盖。
- 一次完整结果对应一层撤销。手动修改结果或改变原生编辑记录后，插件不会强行撤销。
- 最长 90 秒；最多 100000 个草稿字符；自定义响应最多 2 MiB。截断、未完成、工具调用及空结果均不应用。
- 结果和撤销只保存在本页内存，刷新或卸载即清空，请先保留重要草稿。
- 诊断只含时间、耗时、状态、字符数及附带的近期轮次数，不含 Key、URL、原文、结果、会话正文或上游错误正文。
- 调用模型可能消耗额度；服务端日志与数据保留遵循所选提供商的政策。

## 安装到 Harness

使用支持原生 `dsh.bundle.patch` 与 `dsh.client` 的 Web/Desktop 版本。本次已在本机 Harness **0.1.7-rc.2** 的 Desktop 界面安装并验证，不保证旧版兼容。

### Desktop 桌面版

当前这台机器已安装并启用，刷新原来的 Harness 页面即可，无需重复安装。将来重新安装或转移机器时，从 Harness 的插件管理入口安装本发行包的本地 `.tgz` 文件（填写绝对路径），并启用 `dsh-wb-enhance-prompt` 组合包。

**不要运行 `dsh plugin --profile desktop ...`**：本机版本明确将 `desktop` profile 保留给 Electron 应用管理，该 CLI 命令会被拒绝。

### 独立 Web / 自定义 profile

仅当你使用独立 CLI 管理的 Web profile 时，可使用以下命令；将 `web` 替换为实际 profile 名称，不要替换为 `desktop`：

```powershell
dsh plugin --profile web add "C:\path\to\dsh-wb-enhance-prompt-2.0.0.tgz"
```

安装后先保留重要草稿，再刷新**原来的 Harness 页面**。插件不需要单独启动 Web 服务。若更新同名 Host 模块，请等待现有任务结束后重启 Harness，以免继续使用进程缓存中的旧模块。

停用时，在「插件」页关闭该组合包即可。停用不删除保存的设置。需要先清除自定义 Key 时，请在增强设置中勾选清除并保存。

## 开发与检查

发行包已包含 `lib/client.js`，使用者不需要安装构建工具。源码的构建及离线测试仅需 Node.js（本机使用 24.x）：

```powershell
node scripts/build.mjs
node --check src/host.js
node --test test/*.test.mjs
```

Host 使用原生认证 `/api/wb-enhance-prompt`；客户端通过 `conversation.input.right` 插槽注册，紧邻模型插槽之前。回填调用原生带 `draftRev` 的 `inputActions.insertText`，而非改 DOM 或读取 React 内部对象。

### 本机验证结果

- 离线测试覆盖 URL、提示词、有界近期会话、完整性校验、JSON/SSE、取消、草稿保护和原生客户端注册。
- 在原有 Harness GUI 的隔离测试浏览器中，使用当前模型完成真实增强，随后撤销回原文；没有发送聊天消息。
- 本地 HTTP 测试接口验证了 Chat SSE、Responses JSON、停止并中止上游连接、生成中编辑不覆盖、截断拒绝、代码变化拒绝、完整结果保留、撤销失效条件和换地址清 Key。
- 远程 HTTP/HTTPS 地址规则已做离线测试；并未声称测试过所有远程服务的兼容性。跟随模式也曾遇到一次未正常完成的返回，当时原草稿保持不变；后续单独手动验证成功。
- 测试结束已恢复为默认跟随模式，移除测试 Key 和临时验证插件。

## 与原分享脚本的区别

这是原生功能移植，不是原脚本直接重命名：由 Codex 全局配置改为当前 Harness 会话模型；增加深度模式；允许远程 HTTP；密钥移到 Host；使用原生编辑器、主题和弹窗。没有移植依赖 Codex 内部结构的轮询、DOM 补丁及逐字节进度显示。独立模式模型名称可直接填写，没有自动拉取模型下拉列表。
